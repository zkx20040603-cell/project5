## 수정 담당자에게 전달할 결함

### A/B 공통: 입력 검증

- 날짜 문자열이 비어 있지 않은지만 확인해 `2026-02-30`을 통과시킨다. 실제 날짜 검증 필요.
- 잘못된 구분을 지출로 처리한다. `수입`/`지출` 외에는 오류로 처리해야 한다.
- 0원 거래는 문서상 허용되지만 A/B 모두 버린다. 허용 정책을 일치시킬 것.
- A는 소수 금액을 정수로 잘라내고 B는 소수를 유지한다. 정수 원화 규격으로 사전 거부해야 한다.
- 실제 빈 장부/통신 실패 시 데모로 대체된다. 실제 장부 모드에서는 오류·빈 데이터 상태와 데모를 명확히 구분할 것.

### B: 문자열 출력·파일 내보내기

- `renderTable`의 날짜/카테고리와 `renderCategoryRanking`의 카테고리가 escape 없이 innerHTML에 들어간다. 시트 문자열은 textContent 또는 escapeHtml로 출력해야 한다. 코드 검토 결과이며 실제 공격 실행은 하지 않았다.
- CSV 내보내기에서 카테고리·결제수단·작성자의 큰따옴표 처리가 빠져 있다. 모든 문자열 필드에 동일한 CSV 인용 처리를 적용하고 스프레드시트 수식 접두어를 안전하게 처리할 것.
- `LAST_3_MONTHS`의 setMonth 전에 일자를 1로 설정하지 않아 월말에 시작월이 밀릴 수 있다. 월말 날짜 회귀 테스트 필요.
- 가이드 모달 이벤트의 세 번째 인수에 classList 변경을 전달한다. flex 변경은 이벤트 콜백 내부에서 수행해야 한다.

### 샘플 CSV 소유자

`data/sample_accounting_data.csv` 10행의 `화이트보드 마카, 포스트잇 및 사무용품` 필드가 인용되지 않아 9열로 해석된다. 해당 필드를 큰따옴표로 감싸야 한다. 정상 TSV는 그대로 사용 가능하다. C는 기존 샘플을 덮어쓰지 않았다.

### A: 배포 연동

현재 deploy.yml에는 수집 실행·schedule이 없다. B는 생성 JSON을 사용하지 않고 CSV를 직접 읽는다. A 완료 전에 최종 데이터 경로를 확정하고 C 실데이터 대사 재실행이 필요하다.

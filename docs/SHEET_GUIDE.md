# 회계장부 입력 규격과 사용자 안내

## 대상

- 편집 링크(현재 index.html의 링크, 계정 권한 필요): https://docs.google.com/spreadsheets/d/1lJE_yZnl5Bw1YpHJ67gRaoYv0aOUt7BXULHM1_Hu2wE/edit
- 공개 조회/CSV 주소: README의 프로젝트 공용 구글 시트 링크 사용.
- 편집 파일과 게시 CSV가 같은 원본인지 실제 행으로 대조하기 전에는 연결을 확정하지 않는다.

## 표 구조

첫 행은 다음 순서를 유지한다. 병합 셀, 제목 행, 중간 합계 행을 데이터 범위에 넣지 않는다.

| 열 | 이름 | 필수 | 규칙 |
|---|---|---|---|
| A | 일자 | 예 | 실제 유효한 날짜, 표시 YYYY-MM-DD |
| B | 구분 | 예 | 수입 / 지출 |
| C | 카테고리 | 예 | config/accounting_schema.json의 categories |
| D | 항목명 | 예 | 공백만 있는 값 금지 |
| E | 금액 | 예 | 원화 정수, 0 이상; 지출도 양수 |
| F | 결제수단 | 아니오 | config의 payment_methods 또는 공란 |
| G | 작성자 | 아니오 | 공개 가능한 팀 내 별칭 권장 |
| H | 비고 | 아니오 | 공개 가능한 설명만 입력 |

현재 A/B 코드는 0원 행을 제외한다. 규격은 원래 C 문서대로 0을 허용하며 이 차이는 QA 인계 항목으로 남긴다. JavaScript 안전 정수 최대값은 9007199254740991이며 합산 결과도 범위를 넘지 않아야 한다.

## 실제 시트에 적용할 설정

아래는 적용 절차이며 현재 시트에 적용되었다는 의미가 아니다. 먼저 기존 내용과 탭명을 확인하고 데이터는 덮어쓰지 않는다.

1. 첫 행을 고정하고 A:H에 필터를 설정한다.
2. A2:A: 데이터 유효성 검사에서 유효한 날짜만 허용, 표시 형식 `yyyy-mm-dd`.
3. B2:B / C2:C / F2:F: config의 목록으로 드롭다운, 다중 선택 해제, 잘못된 입력 거부.
4. E2:E: 사용자 지정 수식 `=OR(E2="",AND(ISNUMBER(E2),E2>=0,E2=INT(E2),E2<=9007199254740991))`, 잘못된 입력 거부. 숫자 표시 `#,##0`.
5. A2:H에 조건부 서식 `=AND(COUNTA($A2:$H2)>0,OR($A2="",$B2="",$C2="",LEN(TRIM($D2))=0,$E2=""))`를 적용해 부분 입력 행을 표시한다.
6. 새 행에도 규칙이 적용되는지 확인한다. 빈 셀은 유효성 검사만으로 완전하게 막을 수 없으므로 게시 전 CSV 검사를 병행한다.

## 입력 및 수정

한 행은 한 거래이다. 금액 셀에 `원`이나 수식을 직접 입력하지 않는다. 천 단위 구분은 표시 형식으로 처리한다. 완전히 빈 행은 허용하지만 부분 입력 행은 수정한다. 분류 변경 시 config, 시트 드롭다운, 테스트 데이터를 함께 검토한다.

기존 `data/copy_paste_to_sheets.tsv`는 데모 20건이다. 실거래 장부에 무단 추가하지 않는다. CSV 파일을 직접 수정할 때 쉼표가 포함된 항목명은 큰따옴표로 감싸야 한다.

## 화면 사용

새로고침 버튼은 공개 CSV를 다시 읽는다. 게시 변경 반영에는 시간이 걸릴 수 있다. 샘플 데이터 모드 표시가 보이면 실제 장부의 합계가 아니다. 현재 필터는 거래 목록과 CSV 추출에 적용되며 상단 합계·차트는 전체 거래 기준이다.

계좌번호, 주민번호, 접근 토큰, 비공개 영수증 주소를 입력하지 않는다. 현재 작성자와 비고도 브라우저에 전달된다. 프런트엔드 PIN은 공개 CSV 보호 수단이 아니다.
